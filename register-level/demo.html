一、AI 开发好在哪（本工程就是证据）

零学费，门槛只剩「装软件」

手册 1700 页不用啃。RM0090 每个寄存器位段、BRR 波特率实算 （84MHz/16/115200 → BRR=0x2D9，误差 +0.023%）、 CAN 位时序采样点 85.7%，AI 直接算好写进代码注释。

你只需要会：装软件、接杜邦线、敲回车。

快：一下午 = 21 个外设模块

从一句「把所有外设都用上」到编译零错误零警告的 hex， AI 完成引脚预算（82 脚分到 97.6%）、14 组引脚冲突裁决、 CubeMX 配置、21 个驱动模块、26 条验证命令。

人工做同样的事，按教程书速度是一个季度。

可验证：不靠「我觉得能用」

每个模块自带 selftest()，串口菜单逐个跑， 输出机械判据 PASS / FAIL step<N>。 DAC 输出用 ADC 实读对账、PWM 用输入捕获实测频率—— 三角验证：手册怎么说 → 代码怎么写 → 板上测到什么。

教学级：每行代码带出处

写 BDTR.DTG=0x94 旁边就注释 「168MHz→t_DTS=5.952ns→死区 999.9ns」； 写错的地方 AI 会被手册打回重写 （本次开发中被纠正 7 处，全部留痕）。

比很多教程更严谨：以手册为唯一权威源。

二、AI 开发方法：四步循环

1

说需求（人）

一句话即可：「把 F407 所有外设都用上，每个外设单独 .c/.h，带测试和注释」。

2

AI 拆解 + 出方案（AI 提案 → 你拍板）

AI 先做可行性：引脚预算矩阵（哪些脚被焊死、哪些外设冲突）、 给出 2~3 个方案对比表，方向由你选定后动工。

3

生成代码 + 配置（AI）

CubeMX 配置 → 驱动模块 → 菜单测试框架 → 配套文档，一次产出。

4

构建 + 上板验证（机械判据说话）

编译三判据（退出码 / 0 错 0 警 / hex 时间戳）→ 烧录 → 串口逐模块 PASS。报错把日志原样贴回给 AI，它修。

四、大概过程（从零到 hex）

1

装软件 + 接板子

上表装完，板子双 Type-C：左口用户 USB，右口 DAP（供电+调试+串口三合一）。

2

对 AI 说需求

例如「建一个工程把所有外设用上，每个外设单独文件带测试」。AI 先回方案表，选一个。

3

AI 生成工程

CubeMX 配置 + 各外设模块 + 串口菜单 + 文档。本例真实产出见 projects/f407-periph-lab。

4

构建（一条命令）

python -m autostm32.cli build --project projects/f407-periph-lab → 三判据自动判定，不过贴日志给 AI。

5

烧录 + 上板逐模块验证

串口敲 help，按下面第五节的表逐条跑 PASS。

五、验证准备（照单备齐，5 分钟）

硬件清单

① F407VE 开发板 v5.5
② Type-C 线 ×2：右口（DAP）接电脑 = 供电+烧录+串口；左口（USB Slave）给 USB 实验用
③ 杜邦线 ×2（母对母）：PA4→PB0、PA8→PB3
④ （可选）示波器/逻辑分析仪

软件就位确认

① 设备管理器能看到 CMSIS-DAP（VID 0416）和虚拟串口（COMx）
② hex 已生成：firmware/MDK-ARM/f407-periph-lab/f407-periph-lab.hex
③ Keil 工程 .uvoptx 调试器选 CMSIS-DAP（不是 ST-Link！这是本板第一坑）

六、操作指导（烧录后照表跑）

接线口诀：黄线 PA4→PB0（DAC 出、ADC 进）；蓝线 PA8→PB3（PWM 出、捕获进）。 就两根，插错也不烧板——最多命令 FAIL，拔掉重插即可。
串口输入预期输出（判据）需要接线
