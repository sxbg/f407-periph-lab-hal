一、AI 开发好在哪（本工程就是证据）

零学费，门槛只剩「装软件」

手册 1700 页不用啃。RM0090 每个寄存器位段、BRR 波特率实算 （84MHz/16/115200 → BRR=0x2D9，误差 +0.023%）、 CAN 位时序采样点 85.7%，AI 直接算好写进代码注释。

你只需要会：装软件、接杜邦线、敲回车。

快：一下午 = 21 个外设模块

从一句「把所有外设都用上」到编译零错误零警告的 hex， AI 完成引脚预算（82 脚分到 97.6%）、14 组引脚冲突裁决、 CubeMX 配置、21 个驱动模块、26 条验证命令。

人工做同样的事，按教程书速度是一个季度。

可验证：不靠「我觉得能用」

每个模块自带 selftest()，串口菜单逐个跑， 输出机械判据 PASS / FAIL step<N>。 DAC 输出用 ADC 实读对账、PWM 用输入捕获实测频率—— 三角验证：手册怎么说 → 代码怎么写 → 板上测到什么。

教学级：每行代码带出处

写 BDTR.DTG=0x94 旁边就注释 「168MHz→t_DTS=5.952ns→死区 999.9ns」； 写错的地方 AI 会被手册打回重写 （本次开发中被纠正 7 处，全部留痕）。

比很多教程更严谨：以手册为唯一权威源。

七、HAL 版开发全程实录（CubeMX 配置 + HAL API，一天完成并上板闭环）

1目标：客户要的「CubeMX 版」

寄存器版教学价值高，但客户主线需要 CubeMX 可重生成： 外设由图形化配置生成 MX_*_Init，应用层直接调 HAL_*。 于是双轨并行：寄存器版（教学深挖）+ HAL 版（生产主线）， 菜单命令名、模块划分完全对齐，客户按需选用。

2配置先行：22 个外设参数一张表

动手前先出 config-spec：CAN 500k = 7/8tq/3tq、SPI /16 = 5.25 MHz、 IWDG 8.19 s、ADC 四 rank 采样窗……每个参数带出处。 .ioc 文本规则逆向 14 组对照实验（键序 / 白名单 / VP 枚举）， 22 个外设的参数层全部文本化落地、可重放。

3模拟外设攻坚（最难的一公里）

ADC/DAC/DMA 无法文本实例化（官方 loader 盲区）：CLI 命令表逐条核过 （最新 6.18.0 与 6.11 相同，无配置命令）、GitHub 无先例、 8 组对照实验画出能力矩阵。最终路径：GUI 一次激活 ADC1/DAC（勾通道） + 参数层 / DMA 全文本补齐 + 官方板卡基底迁移实验（config saveas roundtrip）。

421 个 bsp 模块重写（5 个 AI 并行）

寄存器版 → HAL 版机械重写，5 个 AI 并行分组（TIM 族 / 模拟类 / 存储类 / 总线系统类 / 电源显示类），统一契约：console-free（自测只返回步号）、 A3 红线（禁止寄存器写入，只读探测需注释豁免）、armcc C99 规范。

八、上板排障：8 案全部 SWD 取证闭环

首次上板连撞多雷、症状互相掩盖（串口静默 = 最早的雷挡住启动，后面全被遮住）。 取证四板斧（pyocd，CMSIS-DAP 的 SWD 通道）：

板斧 1 · halt 读 PC/LR

栈回溯 + map 反查符号，一击定位死点。三次命中： Error_Handler（SDIO 死挡）、空 DMA handler（中断风暴）、菜单喂狗点（时序）。

板斧 2 · 外设寄存器实况读

区分「代码写对但硬件没跟上」：DAC DOR=621（500mV 码 ✓）而 PA4 MODER=AF ✗——数字通路全对、引脚模式被遗留配置顶掉，一眼锁定。

板斧 3 · RAM 搜 RTT magic

「SEGGER RTT」控制块由运行时初始化写入——不存在 = 固件从未活过启动， 直接排除后半段所有嫌疑，聚焦启动路径。

板斧 4 · 直写 flash 寄存器

pyocd 手动模拟 unlock→program：写入成功 = 硬件正常、锅在固件路径， 一轮实验终结硬件/软件之争。

8 个雷（症状 → 根因 → 修复 → 验证）

雷 1 · SDIO 空座砖机

症状：烧录后串口全静默，无卡即死。
根因：生成代码把 HAL_SD_Init 失败当致命错误。
修复：lazy return + 运行时自配。
验证：PASS SDHC mfr=0x02 7386MB

雷 2 · WWDG 64 窗剃刀

症状：启动 ~49ms 复位循环。
根因：生成器恒输出单 tick 刷新区（0.78ms），任何启动序列都不可能命中。
修复：调试期看门狗全关（用户裁定，恢复方法已文档化）。
验证：KNOWN 启动稳定进菜单

雷 3 · DMA 空 handler 中断风暴

症状：DMA-TX 发出后菜单被饿死。
根因：生成的 handler 体为空，TCIF 永不清。
修复：USER CODE 区补 HAL_DMA_IRQHandler。
验证：PASS USART1_TX 闭环

雷 4 · EXTI 空 handler 按键风暴

症状：KEY2 一按菜单死。
根因：同族盲区，PR 挂起位永不清。
修复：USER CODE 区补 HAL_GPIO_EXTI_IRQHandler。
验证：PASS exti (3 presses)

雷 5 · flash sector_error 永远误报

症状：flash_iap 稳定 FAIL。
根因：HAL 把 *SectorError 预置 0xFFFFFFFF（成功即保持），调用方按 0 初始化。
修复：按 HAL 约定判定 + 擦前清脏标志。
验证：PASS erase ok, param 8w kept

雷 6 · tim_basic 守护先死

症状：稳定 FAIL（寄存器实况全健康）。
根因：固定 2M 圈守护 ≈120ms，比 1.5s 窗口先耗尽。
修复：HAL_GetTick 进展则重置守护。
验证：PASS 连续多轮稳定

雷 7 · ADC 采样窗 × 杜邦线

症状：PC0 读恒 0（示波器实测 PA4=512mV 正常）。
根因：3-cycle 采样窗 143ns 对杜邦线接驳阻抗不足，采样电容欠充。
修复：CH10 固化 480 cycles。
验证：PASS 501/1657/2802 vs 500/1650/2800（≤8mV）

雷 8 · DAC 输出到不了引脚

症状：寄存器全对（DOR=500mV 码），引脚无输出。
根因：.ioc 遗留 PA4=AF 模式（DAC 要求 Analog）。
修复：bsp 层自持 HAL_GPIO_Init(Analog)。
验证：PASS 示波器实测 PA4=2.8V
