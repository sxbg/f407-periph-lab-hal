工程与验证方法

目标架构：外设由 CubeMX 图形化配置生成 MX_*_Init，应用代码直接调用 HAL API（bsp 层 console-free、A3 红线禁止寄存器级写入）。工程三层： Core/（CubeMX 生成）+ App/（bsp/shell/domain）+ Drivers/。

时钟：HSE 25 MHz → PLL(M=25,N=336,P=2) → SYSCLK 168 MHz；APB1 /4=42 MHz （TIM ×2=84 MHz）；APB2 /2=84 MHz；PLLQ=7 → 48 MHz（SDIO/RNG）。

验证方法：UART 命令菜单（USART1 115200 8N1，tools/menu_autotest.py 同步驱动）逐模块执行自测，判据 PASS/FAIL step<N>；闭环项以杜邦线互证 （DAC→ADC、PWM→捕获）；pyocd(CMSIS-DAP/SWD) 做寄存器级取证。

本报告数据来源：docs/test-report.md（最终回归 PASS 19 / KNOWN 1 / FAIL 0）、 docs/periph/ 22 页、knowledge/pitfalls-cubemx-keil.md #17/#18。

PASS菜单命令：uart

bsp_uart — USART1 日志控制台（EP03）

本模块教：CubeMX 把串口配成什么（生成代码即真值）、应用层怎么用 HAL_UART_* 轮询收发、以及如何用读回校验确认配置未被破坏。USART1 是菜单 shell 的承载口；寄存器版（CR1/BRR 手写）细节见 f407-periph-lab 工程同名文档。

CubeMX GUI 配置步骤

  1. 时钟树（Clock Configuration，三串口共用）：HSE 25 MHz → PLL（M=25, N=336, P=2）→ SYSCLK 168 MHz；APB1 Prescaler = /4 → 42 MHz，APB2 Prescaler = /2 → 84 MHz（USART1 内核时钟 = PCLK2 = 84 MHz）。
  2. 左侧 Categories → Connectivity → USART1：Mode 选 Asynchronous（异步 8N1，无外时钟脚）。
  3. Parameter Settings（与生成代码 MX_USART1_UART_Init 一一对应）：

- Baud Rate = 115200（84 MHz 下实测误差 +0.023%，远小于 8N1 ~2% 预算）

- Word Length = 8 Bits（含校验位）；Parity = NONE；Stop Bits = 1

- Mode = TX_RX；Hardware Flow Control = NONE

- Over Sampling = 16（对应 BRR = 0x2D9：USARTDIV = 84M/16/115200 = 45.5729 → 尾数 45、小数 round(0.5729×16)=9）

  1. DMA Settings：USART1_TX → DMA2 Stream7 / Channel4，Memory→Peripheral，Normal，Low 优先级（详见 dma.md；本模块不用 DMA）。
  2. NVIC Settings：USART1 中断不开——轮询教学基线。
  3. USART2（PA2/PA3）、USART3（PB10/PB11）重复步骤 2-3：同为 115200 8N1、TX_RX、无 DMA、无中断。

生成真值锚点（Core/Src/usart.c）：BaudRate=115200; WordLength=UART_WORDLENGTH_8B; StopBits=UART_STOPBITS_1; Parity=UART_PARITY_NONE; Mode=UART_MODE_TX_RX; HwFlowCtl=UART_HWCONTROL_NONE; OverSampling=UART_OVERSAMPLING_16。引脚由 HAL_UART_MspInit 配置：AF 推挽、无上下拉、Very High speed、AF7。

HAL API 调用清单

bsp_uart 对外 4 个函数；自测返回 0=PASS、非零=失败步号，判据行由 shell 层打印（uart 自身即控制台，失败诊断由它直接输出）。CubeMX 拥有外设，本模块只做读回校验 + HAL 收发（A3 红线：不写外设控制寄存器）。

bsp 函数对应 HAL 调用一句作用
int bsp_uart_init(void)读回 huart1（BRR=0x2D9 + UE/TE/RE）校验 CubeMX 配置完好（只读，-1=失配）
void bsp_uart_puts(const char *s)HAL_UART_Transmit（32 字节分段，超时上限 5 ms/字节）阻塞发字符串；TX 卡死即返回，不挂菜单循环
int bsp_uart_getc_nonblock(void)HAL_UART_Receive(&huart1, &b, 1, 0)（0 tick 超时）非阻塞收一字节：0..255，无数据 = -1（HAL_TIMEOUT）
int bsp_uart_selftest(void)上述组合3 步自测（见下节）

典型调用：


#include "bsp_uart.h"

bsp_uart_init();                        /* 0 = 生成配置完好 */
bsp_uart_puts("hello 115200 8N1\r\n");  /* HAL_UART_Transmit 轮询发送 */
int c = bsp_uart_getc_nonblock();       /* HAL_UART_Receive 零超时收键 */

bsp_tim_pwm — TIM1/TIM4 PWM 输出（EP06）

本模块教：CubeMX 只生成定时器基础 init（PSC=0/ARR=max/CEN=0），通道形状（PWM 模式/PSC/ARR/占空）由 HAL_TIM_PWM_* 在运行时写；TIM1（APB2 ×2=168 MHz，高级）与 TIM4（APB1 ×2=84 MHz，通用）同播 1 kHz。寄存器版（CCMR1/EGR.UG 手写）细节见 f407-periph-lab 工程同名文档。

CubeMX GUI 配置步骤

  1. 左侧 Categories → Timers → TIM1：Clock Source = Internal Clock；Channel1 = PWM Generation CH1（引脚自动落 PA8）。
  2. Parameter Settings（MX_TIM1_Init 真值）：Prescaler = 0；Counter Mode = Up；Counter Period = 65535；auto-reload preload = Disable（ARR 写入立即生效）；Clock Division = DIV1；RepetitionCounter = 0。
  3. Timers → TIM4：Channel1 = PWM Generation CH1（PD12）；参数同上（无 RepetitionCounter）。
  4. 时钟树：TIM1 挂 APB2（PCLK2 = 84 MHz，总线有分频 → 定时器时钟 ×2 = 168 MHz）；TIM4 挂 APB1（PCLK1 = 42 MHz ×2 = 84 MHz）——RM ch.6 规则。
  5. NVIC Settings：两个定时器中断都不开（轮询教学基线）。
  6. 生成代码只到 HAL_TIM_Base_Init（CEN=0，通道未配）；1 kHz 形状由 bsp 模块武装——这是 HAL 版与寄存器版的分工边界。

HAL API 调用清单

bsp_tim_pwm 对外 3 个函数 + 2 个通道选择宏（BSP_TIM_PWM_CH_TIM1_CH1 / BSP_TIM_PWM_CH_TIM4_CH1）；console-free，自测返回 0=PASS、非零=失败步号。通道形状只经 HAL_TIM_PWM_ConfigChannel/HAL_TIM_PWM_Start 和 __HAL_TIM_SET_* 宏写（A3 红线；寄存器读仅作校验）。

bsp 函数对应 HAL 调用一句作用
int bsp_tim_pwm_init(void)HAL_TIM_PWM_Stop → HAL_TIM_PWM_ConfigChannel（PWM1、Pulse=500 预装载）→ __HAL_TIM_SET_PRESCALER/AUTORELOAD/COUNTER → HAL_TIM_PWM_Start（CC1E + TIM1 MOE + CEN 最后置）双通道武装为 1 kHz / 50%（幂等）

HAL_TIM_PWM_ConfigChannel 从结构体写 CCMR1/CCR1，全字段真值：OCMode=TIM_OCMODE_PWM1（CNT<CCR 时有效）、Pulse=500（50% 预装载）、OCPolarity=TIM_OCPOLARITY_HIGH、OCFastMode=TIM_OCFAST_DISABLE、OCIdleState=TIM_OCIDLESTATE_RESET（MOE 清掉后引脚静止在低）。

频率两步分频（两个定时器共用同一公式）：f_tick = f_tim/(PSC+1)，f_frame = f_tick/(ARR+1)。TIM1：168M/(167+1) = 1 MHz tick，/(999+1) = 1 kHz；TIM4：84M/(83+1) = 1 MHz。内核时钟差 2:1，终值刻意同为 1 MHz/1 kHz——占空数学共享。

典型调用：


#include "bsp_tim_pwm.h"

bsp_tim_pwm_init();                                  /* 双通道 1 kHz 50% */
bsp_tim_pwm_set_duty(BSP_TIM_PWM_CH_TIM1_CH1, 250);  /* PA8 → 25% 占空 */
bsp_tim_pwm_set_duty(BSP_TIM_PWM_CH_TIM4_CH1, 0);    /* PD12 → 常低 */

生成器盲区备注

  • PSC 影子寄存器 + EGR.UG 盲区：PSC 写入在下一个更新事件才锁进影子，而 HAL 没有 EGR.UG 立即装载的拼写——Start 后第一帧按旧 PSC=0 跑（TIM1 ~6 µs / TIM4 ~12 µs），之后 1 kHz 节拍锁定。教学上接受，代码写点处有注释。
  • TIM1 BDTR MOE：由 HAL_TIM_PWM_Start 内部置位；少了它 CCER 全开 PA8 也是平线——高级定时器第一坑，自测步 3 专查。
  • 幂等重配：HAL 通道状态机 BUSY 时再 Start 是 HAL_ERROR，所以 init 先 HAL_TIM_PWM_Stop 恢复 READY 并掉 CC1E/MOE/CEN（寄存器版直接写 CR1=0 的 HAL 等价物）。
  • ARPE = Disable（IOC 真值）：ARR 写入立即生效，无影子延迟。

1 Hz 推导（与 PWM 同一条两步分频律）：f_UPDATE = 84 MHz/(PSC+1)/(ARR+1) = 84M/8400/10000 = 1 Hz → PSC = 8399（84M→10 kHz）、ARR = 9999（10 kHz→1 Hz）。

#include "bsp_tim_basic.h"

bsp_tim_basic_init();                          /* TIM5 1 Hz，中断不开 */

生成器盲区备注

  • PSC 影子 + EGR.UG 盲区：PSC 在首个更新事件才装载，HAL 无 UG 拼写 → Start 后第一段 ~119 µs（10000 tick @84 MHz）后才进入 1 Hz 节拍；且 MX_TIM5_Init 的 UG 会留下一个 pending UIF，init 里 __HAL_TIM_CLEAR_FLAG 清掉（老版 SR = ~UIF 的 HAL 拼法，rc_w0 写 0 清除）。

模块公开 API（bsp_pwr.h）：

  • int bsp_pwr_init(void) — 开 PWR/SYSCFG 门控（__HAL_RCC_PWR_CLK_ENABLE 等），只读回读 LPDS/PDDS/SLEEPDEEP 静息态。0=PASS。
  • uint32_t bsp_pwr_sleep_ms(uint32_t ms) — Sleep 毫秒延时：循环进 Sleep，每次 WFI 由 1 ms SysTick 中断唤醒并计一次 COUNTFLAG；TICKINT 若被关，HAL_ResumeTick() 临时武装、事后 HAL_SuspendTick() 还原（WFI 零中断会永久睡死）。SysTick 疑死返回 BSP_PWR_SLEEP_DEAD_SYSTICK（有界退出）。
  • void bsp_pwr_enter_stop(void) — Stop 全流程：清残留 __HAL_GPIO_EXTI_CLEAR_IT(KEY1_Pin)（挂起未清 = Stop 进入被忽略，RM 表注）→ 进 Stop → 唤醒后 SystemInit() 重跑——Stop 退出系统时钟落回 HSI 16 MHz 且 PLL 关，老波特率会喷 ~10.9 kBd 垃圾（EP17 教训）；SystemInit 幂等，重跑即回 168 MHz。
  • void bsp_pwr_arm_standby(void) — __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU) 后进 Standby。函数不返回：寄存器/SRAM 全丢，唤醒 = 复位级启动（硬件唤醒源：WKUP1 上升沿 = 本板 KEY1、RTC 闹钟/唤醒/入侵、NRST、IWDG）。
  • int bsp_pwr_standby_flag(void) — __HAL_PWR_GET_FLAG(PWR_FLAG_SB)：1=上次启动来自 Standby 唤醒（__HAL_PWR_CLEAR_FLAG(PWR_FLAG_SB) 清除）。
  • void bsp_pwr_on_exti0(void) / uint32_t bsp_pwr_exti0_wake_count(void) — 唤醒钩子（一次 volatile 自增）与读数。
  • int bsp_pwr_selftest(void) / const char *bsp_pwr_last_report(void) — 自测与一行报告。

uint32_t slept = bsp_pwr_sleep_ms(100);   /* Sleep: SysTick 逐毫秒唤醒 */
/* menu> pwr_stop_demo 后按 KEY1： */
if (bsp_pwr_exti0_wake_count() > 0u) { /* 唤醒确实走了 EXTI0 */ }

回调路由（A3 红线）：HAL_GPIO_EXTI_Callback 的 weak 覆盖全工程只有一份，由 bsp_exti.c 统一按 GPIO_Pin 分发——KEY1_Pin 分支调 bsp_pwr_on_exti0() 钩子计数，本模块不自建回调（两处强覆盖链接期冲突）。Stop 不进自测：pwr_stop_demo 从菜单 demos 触发，醒后 shell 打印 wake count 作为 EXTI 路径证据；睡眠期心跳停摆会被 logcheck 判"挂死"，属预期；唤醒失败救援 = SWD 复位。Standby 保持 API-only（进入即掉电）。

HAL 调用底层语义（寄存器深讲指引：老工程 flash_iap.md 表 3）：

协议要点（24C02）：

  • 7 位地址 0b1010_000 = 0x50（A2/A1/A0 接地）；HAL 全部调用要 8 位形 dev7 << 1 = 0xA0/0xA1（每事务 HAL 超时 20 ms ≈ 100× 余量，卡死总线快速失败）。
  • 错误分类判据：失败后 HAL_GPIO_ReadPin 读双线——双高 = 总线健康、是器件 NACK（−1）；有线拉低 = 总线卡死（−2）。分类逻辑与软引擎时代一致，只换了裁判。
  • 256 B 存储阵列，字地址单字节；页 = 8 B 且页内低 3 位回绕——跨页写会回卷覆盖页首而非顺延（本模块只做单字节写永不跨页；分块页写是 EP11 练习）。
  • 每次写后 ≤5 ms 内部写周期（tWR），期间器件对一切 NACK——ACK 轮询是 EEPROM 标准等法；跳过轮询 = "写后立刻读回旧值"的经典 EEPROM 教训。
  • 自测先扫 0x50..0x57（整个 1010+A2A1A0 块）精化地址。
  • 寄存器深讲（CCR=210/TRISE=43/EV5–EV8_2 清除对/SR1+SR2 读对）压缩一句指引：见老工程 i2c_ee.md 表 3——时序与事件机已由 HAL 包办。
  • 引擎迁移一览：软总线引脚电气 = MspInit 生成；半位时序公式 = HAL_I2C_Init 数学；ACK 槽探针 = HAL_I2C_IsDeviceReady；9 时钟总线恢复 = HAL 错误路径复位外设（重跑 init 即恢复，留作扩展练习）。

#1 症状：烧录后串口完全静默（菜单无 banner，无任何输出）

验证PASS sdio_tf (SDHC mfr=0x02 7386MB)
#2 症状：复测时板子再次失联，halt 抓到 PC=EXTI1_IRQHandler 入口、LR=EXC_RETURN
取证中断返回后立即重入 = 中断风暴。生成的 EXTI1_IRQHandler 体为空（TC/PR 挂起位永不清），KEY2 按键触发即风暴，菜单被饿死。

修复调试期看门狗全关（用户裁定）：MX_IWDG_Init/MX_WWDG_Init 的USER CODE 0 区短路。恢复 = 删两处 return + bsp_wdg 运行时 init。
验证启动后稳定进入菜单；wdg 记 KNOWN（预期偏差）。
#4 症状：tim_basic 稳定 FAIL（step1/step2 漂移）
取证TIM5 寄存器实况全部健康（CEN=1、PSC=8399、ARR=9999、CNT 翻转）。代码审查：SPIN_GUARD 固定 2M 圈 @168MHz ≈ 120 ms，比 1.5 s 窗口先耗尽——guard 永远先于 update 死亡。
根因固定圈数守护未按窗口长度校准（2M 圈 × ~60 ns/圈 ≈ 120 ms）。
修复改为 tick-进展重置式守护：HAL_GetTick 有进展即重置 guard（SysTick 死检测语义保留）。
验证PASS tim_basic（连续多轮稳定）
#5 症状：flash_iap 稳定 FAIL step2（无 report 后缀）
取证现场读参数页/扇区头全 0xFF（擦除其实成功、写入未执行）；pyocd 手动模拟 unlock→program 写入成功（硬件正常）。HAL_FLASHEx_Erase 把 *SectorError 预置 0xFFFFFFFF（成功即保持），调用方以 0 初始化 + !=0 判据永远误报。
根因HAL 约定坑（知识 #18）：sector_error 的成功语义；另有 SR 脏错误位（WRPERR/PGSERR 残留）导致新操作立即报错。
修复按 HAL 约定 0xFFFFFFFF 初始化并判定；擦除前 __HAL_FLASH_CLEAR_FLAG 清脏标志；step2 全分支接入 report。
验证PASS flash_iap (erase ok, param 8w kept)
#6 症状：dac_adc_loop 读 PC0 恒 0（浮空脚也恒 0）
取证SWD 实况：DAC DOR=0x26D（500mV 码 ✓）、DHR ✓、CR ✓——数字通路全对；GPIOA MODER PA4=AF（非 Analog）→ DAC 输出到不了引脚。示波器实测 PA4=512mV→修复后 2.8V（第三 setpoint）。ADC 侧：CH10 3-cycle 采样窗 143ns，RM0090 源阻抗上限 ~200Ω，杜邦线接驳阻抗下采样电容欠充 → 读恒 0。PC4 读数跟随时序漂移 = rank3 读到 rank2 残压（采样保持活教材）。
根因三重叠加：PA4 .ioc loader 遗留 AF 模式（知识 #18）+ CH10 3-cycle 采样窗对杜邦线阻抗不足 + 浮空脚短采样保持特性。
修复bsp_dac_init 自持 HAL_GPIO_Init(PA4 Analog)；CH10 固化 480 cycles（实测 501/1657/2802 vs 500/1650/2800，≤8 mV）；浮空脚零读数写进教学注释。
验证PASS dac_adc_loop（连续多轮）、PASS dac、PASS adc (vrefint 1205mV)
#7 症状：gpio/tim_pwm 命令字符偶发丢失（'gpiotim_pwm' 粘连）
取证help/banner 打印期间 HAL_UART_Transmit 阻塞，RX 到达的字节置 ORE（溢出），溢出后新字节全部被抑制——菜单饿死在打印期间。
根因F4 UART ORE 置位后 RX 被抑制，无人清除。
修复bsp_uart_getc_nonblock 检测 ORE 并 __HAL_UART_CLEAR_OREFLAG 清除 +补一次 DR 读；脚本侧加 menu> 提示符同步（打印完成才发命令）。
验证自动套件 22 项连续跑通，无粘连复现
#8 症状：adc step1 / dac_adc_loop step1 判据漂移
取证F4 HAL_ADC_Init 不置 ADON（Start 才置）；SMP17 只有 2 位（480 cycles 装不下，钳位 56）；F4 HAL ConfigChannel 的 采样时间/rank 映射使静态 SMPR 位探测语义含混。
根因agent 生成代码假设寄存器级行为，与 HAL 语义/硬件位宽不符。
修复探测放宽到硬件可实现域（删 ADON/SMP 位探测，保留 TSVREFE/SQR1/Analog 引脚检查）；采样正确性由 read_mv 实测行为验证（闭环 ≤8mV）。
验证PASS adc (vrefint 1205mV, vdda 3312mV)、PASS dac_adc_loop
